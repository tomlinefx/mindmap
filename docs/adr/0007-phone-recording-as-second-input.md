# スマホの録音を PC の会議に加わる 2 つ目の入力にし、文字起こしは常時起動サーバーで行う

ADR 0003 は Android を「見るだけ」にしたが、PC を開かずに対面の会議を録りたい（Plaud のような使い方）。そこで、スマホのマイクで部屋の音を録って自分のサーバーへ送る「録音」を、PC の会議（ヘルパー）に並ぶ 2 つ目の入力にする。PC の経路は残す。録音は止めたあとにマップを組み立てる（会議の最中にはマップは育たない）。ライブ型は次の段階。

## Consequences

- サーバーは tailnet の中だけに開く常時起動の Linux。文字起こし（端末内 STT）は、ヘルパーの `Transcription`（`ITranscriber`、sherpa-onnx、silero VAD）を Windows に依存しない形で切り出し、サーバーで動かす。ヘルパーの Windows 専用の部分（WASAPI の取得・AEC3）は PC の経路に残る
- 音声がスマホからサーバーへ出る。端末内 STT の約束は「利用者が管理する機器の外に出さない」に言い換える（`CONTEXT.md`）
- 録音の開始・停止は、閲覧の口とは別の口と認証で守る。閲覧の PIN を知っているだけでは録音を始めも止めもできない。閲覧の共有は「見るだけ」のまま
- トラックに `部屋` を足す。スマホの録音では話者を分けず、案の「出した人」も持たない。声で人を分けるのは別の仕様（`speaker-attribution` は `自分` と `相手` が対象で、範囲外）
- 録音を止めたあとの組み立ては、`再生` と同じ経路（`cli play`、既定は待たずに流す）を使う
- スマホ側は PWA で始め、画面オフ・ロック中に録音が続くかを先に検証する。足りなければ薄いネイティブのラッパーを検討する
- ブラウザのマイクには HTTPS が要る。運用側（`tailscale serve` など）で用意し、コードに Tailscale 固有の対応は入れない（ADR 0003 の方針は保つ）
- 同時に扱うセッションは 1 つのまま。PC の会議と録音の一方が進行中は、もう一方を始められない。録音を止めたあとの組み立て中も進行中とみなす
