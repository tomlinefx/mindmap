# 差分更新は、開いた query の中ではマップの変更だけを送る

差分更新は、開いたままの query を 14 回使い回す（[#87](https://github.com/daiki-beppu/live-mindmap/issues/87)）。その中で、マップ全体のアウトラインを送るのは query を開いた最初の呼び出しだけにし、2 回目からは前回からのマップの変更（AI の前回の操作を当てた結果）だけを送る。キャッシュは 5 分 TTL で書く。長い会議では、全体の再送が費用の大半を占め、累計が時間の 2 乗で伸びていた。161 分の会議で、1 時間あたりの費用が $1.82 → $4.19 → $4.91 から $0.82 → $0.78 → $0.70 になり、時間に比例した（[#130](https://github.com/daiki-beppu/live-mindmap/issues/130)）。

## Considered Options

- **毎回マップ全体を送る（今までの作り）**: AI が会話の履歴を頼らずに済むが、1 回の費用がノード数に比例して伸びる。1〜2 分の場面（[#75](https://github.com/daiki-beppu/live-mindmap/issues/75)）では変更分だけ送っても費用が下がらず見送ったが、それはマップが小さかったためで、長い会議では逆になった
- **済みの議題を畳むだけ**: 話し中の議題 1 つが際限なく育つと縮まず、3 時間目の費用が 1 時間目の約 2 倍で残った。済みは畳んで渡す（議題名と論点・決定・TODO、ID つき）が、費用を時間に比例させるのは変更分だけ送る方
- **済みの議題を要約文で渡す**: 要約が議題名の行より長くなって減らず、要約を作る呼び出しも要る

## Consequences

- AI は「最初のマップにこれまでの変更を順に当てたもの」を今のマップとして扱う。変更には add で付いた id を載せ、AI は次の応答で仮 id ではなくその id を使う。適用できなかった操作は変更に出ないので、AI の応答に書いたことでもマップには無いことがある
- query を開き直すとき（回数・失敗・ストリームの終わり）は、必ず全体を送る。開き直した議題・論点は、畳んで渡していた中身ごと変更に載せる
- 161 分の実走では ID の取り違えは 0 件だったが、ノード数が 342 → 200 に減った（update が増えた）。ばらつきとは切り分けていない
