# 共有画面の OCR は語彙のためだけにヘルパーで行い、文字を画面の通知に載せる

ヘルパーは、変化の判定で送ると決めた画面（顔の一覧も含む）を Vision で OCR し、認識した文字の行を画面の通知に載せてサーバーへ送る。サーバーはその文字を `log.jsonl` に残し、カタカナ・漢字・英字の規則で語彙の候補を取る。OCR の文字は語彙にだけ使い、差分更新の読み解きには今までどおり画像だけを渡す。[#183](https://github.com/daiki-beppu/live-mindmap/issues/183) で「ヘルパーに OCR は足さない」と決めたのは読み解きについてで、OCR の文字ではグラフの数字とラベルの対応が崩れるためだった。語彙では語の表記だけが要るので、この欠点は効かない。正しい表記の一番の出どころが共有画面であることは [#391](https://github.com/daiki-beppu/live-mindmap/issues/391) で確かめた（[#510](https://github.com/daiki-beppu/live-mindmap/issues/510)）。

## Considered Options

- **サーバーが画像を受けるたびに、ヘルパーのサブコマンドで OCR させる**: 語の読みを作るときと同じ形になる。ただし、再生や Linux の CI でもヘルパーが要るうえ、画面ごとに往復が要る
- **一定の間隔で別に読む**: 変化の判定ですでに画面を絞っているので、同じ画面を読み直すだけになる
- **ヘルパーが候補まで取り出して送る**: 取り方を変えたときに、録音からやり直さないと測り直せない

## Consequences

- WebSocket はヘルパーからサーバーへの一方向のままにする
- Vision は端末の中で動くので、ローカルモードでも同じに動く
- 画面収録の許可が無いときや OCR が失敗したときは、共有画面からの語彙なしでセッションを続ける
- OCR の文字が無い古いログの画面からは、候補を取らない
