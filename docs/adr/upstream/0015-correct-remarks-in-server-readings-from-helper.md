# 語彙での補正はサーバーが発言を締めるときにかけ、読みはヘルパーが送る

語彙での補正（読みの索引で決定的に置き換える形。[#393](https://github.com/daiki-beppu/live-mindmap/issues/393)）は、サーバーの中核が発言を締めて出す直前にかける。発言は確定結果からも、1 秒更新されなかった途中結果からもサーバーが作るので、その出口の 1 か所なら取りこぼさない。照合に使う読みは、ヘルパーが `remark` / `partial` に語ごとの表記・読み（OS のトークナイザのローマ字）・本文の中の文字位置として載せて送る。読みを取る手段は Swift の側にあり、測った値もその読みで出ているためである（[#490](https://github.com/daiki-beppu/live-mindmap/issues/490)）。

## Considered Options

- **ヘルパーが確定結果を出す前に直す**: 途中結果から作る発言を通らない。途中結果まで直すと「途中結果は語彙で直さない」に反する。ADR 0013 で話者をヘルパーで載せなかったのと同じ理由である
- **サーバーが発言ごとにヘルパーへ読みを問い合わせる**: 発言ごとに往復が要り、再生や Linux の CI でもヘルパーが要る
- **Node の形態素解析（kuromoji など）で読みを取る**: サーバーの中で閉じるが、測った読みとは別物になるので測り直しが要り、辞書の分だけ重くなる

## Consequences

- 語彙はセッションの状態としてサーバーが持つ。出どころ（共有画面・過去のセッションから引き継いだ語彙・利用者の入力）は候補を渡すだけで、語彙に入れるかはサーバーが決める
- 語彙の語の読みは、ヘルパーの実行ファイルのサブコマンドに語をまとめて渡し、語彙に入るときに 1 度だけ作る（OS のトークナイザ）。WebSocket はヘルパーからサーバーへの一方向のままにする。読みが返らない語は補正に使わず、セッションは止めない
- 英字の語（略語を除く）は、サーバーがセッションの差分更新のモデルに新しい語をまとめてカタカナの読みを聞き、そのカタカナをサブコマンドに渡して読みにする。当初は FoundationModels に聞く形だったが、4 語に 1 語の読みが別の語に崩れた（Amplitude→アスペクト）。差分更新のモデルなら 106 語中 103 語が正しい（[#577](https://github.com/daiki-beppu/live-mindmap/issues/577)）。ローカルモードでも差分更新のモデルは自前の子プロセスなので、会議の中身は Mac の外に出ない
- 発言の後ろだけを新しい発言にするときは、語の並びも文字位置で同じところで切る
- `log.jsonl` の発言の行には、直した本文に加えて、直す前の本文と語ごとの読みを残す。語彙の変化は時刻つきの行で残す。再生では直す前の本文から今の規則で直し直すので、規則や守りを変えても録音からやり直さずに測れる。サーバーが落ちたときの復元は、これまでどおり記録した差分操作を当て直す。読みを持たない古いログの発言は直さずに流す
